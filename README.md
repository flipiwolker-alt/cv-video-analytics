# CV Video Analytics

Сервис автоматического поиска нежелательного контента в видео. На вход — ссылка на YouTube или локальный видеофайл, на выходе — структурированный JSON-отчёт: что нашли, в какие секунды, с какой уверенностью, плюс нарезанные клипы и кадры-превью.

Работает локально, на одной видеокарте (CUDA). Есть два интерфейса: визуальный **Gradio UI** и **REST API** (FastAPI).

---

## Что сервис делает прямо сейчас

1. Скачивает видео (yt-dlp) или принимает загруженный файл.
2. Извлекает информативные ключевые кадры (смена сцены + равномерная выборка + выбор резкого кадра + дедуп).
3. Параллельно прогоняет видео через **8 независимых каналов детекции** (речь, текст в кадре, объекты, сцена, NSFW, действия, плюс необязательный LLM-слой).
4. Сводит все срабатывания воедино: склеивает по времени, повышает уверенность при согласии каналов, режет слабые срабатывания по порогу.
5. Возвращает отчёт с тайм-кодами и при наличии Ollama — краткое человекочитаемое резюме на русском.

## Где считается: GPU

Весь тяжёлый инференс идёт на **видеокарте (CUDA)**. Устройство выбирается автоматически в [`src/device.py`](src/device.py): если доступна CUDA — `cuda`, на Apple Silicon — `mps`, иначе фолбэк на CPU.

Особенность железа: типовая видеокарта — 8 ГБ VRAM, а каналов сразу несколько и они идут в параллельных потоках. Поэтому:

- доступ к GPU **сериализуется одним локом** (`gpu_guard`): GPU настолько быстрее CPU, что даже последовательный прогон стадий кратно выигрывает, и при этом всё помещается в 8 ГБ;
- включён `expandable_segments` — снижает фрагментацию VRAM и риск OOM;
- между прогонами освобождается кэш VRAM (`empty_cache`).

При старте `run_ui.py` / `run_api.py` печатают баннер с выбранным устройством — видно, что нагрузка реально пошла на GPU:

```
[cv-video-analytics] Вычисления: GPU (CUDA): NVIDIA GeForce RTX 5060, 8 ГБ VRAM
[cv-video-analytics] Модели: offline (из кэша, без сети) — E:\cv_models
```

### Пресеты точности (одна «ручка» точность ⇄ скорость)

Один параметр `preset` раскатывается на размеры **всех** моделей сразу.

| Пресет | Объекты (COCO + open-vocab) | Сцена | Речь (Whisper) | На что рассчитан |
|---|---|---|---|---|
| `fast` | YOLOv11s + YOLO-World s | SigLIP2 base/224 | small | быстрый прогон, черновая проверка |
| `balanced` | YOLOv11m + YOLO-World m | SigLIP2 base/384 | large-v3-turbo | рабочий режим по умолчанию |
| `accurate` | YOLOv11x + YOLO-World x | SigLIP2 so400m/384 | large-v3 | максимум качества |

> «Сложные» прогоны (`accurate`, длинные ролики, все каналы включены) автоматически идут на GPU — отдельно ничего настраивать не нужно, выбор устройства общий для всего пайплайна.

## Архитектура пайплайна

Система анализирует видео в **8 параллельных каналах**, каждый независимо ищет нарушения. Результаты сводятся, фильтруются и (опционально) передаются в LLM-слой для финальной проверки и резюме.

```
Видео (YouTube URL или файл)
          │
          ▼
  Загрузка и подготовка
  yt-dlp / локальный файл → mp4; OpenCV: fps, frame_count, duration
          │
          ▼
  Ключевые кадры (scene detection + stride + sharpness + dHash-дедуп)
          │
   ┌──────┴───────────────── параллельно ──────────────────────┐
   ▼                                                            ▼
АУДИО-ВЕТКА                                              ВИДЕО-ВЕТКА
Whisper → транскрипт                            (один набор кадров на все каналы)
   │                                              │     │      │     │      │
   ▼                                              ▼     ▼      ▼     ▼      ▼
словарь + морфология                            YOLO  SigLIP  NSFW  X-CLIP  OCR
+ деобфускация мата                            +World  сцена Falcon  дейст. ru+en
   │                                              └─────┴──────┴─────┴──────┘
   ▼ (опц.) LLM-классификация речи (Ollama)                  │
   └────────────────────────┬──────────────────────────────┘
                            ▼
            Фьюзия: кросс-модальный boost + temporal NMS + порог
                            │
                            ▼ (опц.) LLM vision-проверка пограничных кадров
                            ▼ (опц.) LLM-резюме на русском
                            ▼
                  JSON-отчёт + клипы + кадры
```

### Подробно по каналам

**Загрузка видео** ([`pipeline.py`](src/pipeline.py)). yt-dlp скачивает YouTube или принимается локальный файл. ffmpeg склеивает видео+аудио в `.mp4`, OpenCV читает метаданные (FPS, кадры, длительность).

**Ключевые кадры** ([`pz1_keyframes.py`](src/pz1_keyframes.py)). Не анализируем все тысячи кадров — выбираем информативные: SceneDetect (границы смены сцены) + равномерный stride + выбор самого резкого кадра по дисперсии Лапласиана + dHash-дедупликация почти-одинаковых. На выходе — 30–150 разнообразных резких кадров на все каналы.

**Речь** ([`pz4_audio.py`](src/pz4_audio.py)). ffmpeg → WAV 16 кГц моно. faster-whisper (CTranslate2) транскрибирует с тайм-кодами; размер модели — по пресету. Словарный матчер с морфологией (rapidfuzz) ловит запрещённые слова во всех словоформах, не путая похожие («ром» ≠ «роман»). Деобфускация мата нормализует leet-замены и символы-маскеры перед матчингом.

**Текст в кадре / OCR** ([`pz3_ocr.py`](src/pz3_ocr.py)). EasyOCR (ru+en) читает надписи, субтитры, баннеры. Спец-предобработка под OCR: апскейл мелких кадров, CLAHE-контраст, тюнинг порогов детектора CRAFT, повороты при отсутствии текста. Распознанный текст проверяется тем же словарным матчером, что и речь.

**Объекты** ([`pz5_yolo.py`](src/pz5_yolo.py)). Два детектора параллельно: классический **YOLOv11** (80 COCO-классов: бутылки, нож и т.п.) и **YOLO-World** (open-vocabulary, zero-shot по текстовым промптам: сигареты, шприцы, оружие, граффити, карты/казино, символика). Детекции маппятся на 12 субклассов.

**Сцена** ([`pz6_clip.py`](src/pz6_clip.py)). **SigLIP 2** кодирует каждый кадр и сравнивает с ансамблем промптов по категориям. Введён нейтральный baseline: срабатывание только если score категории превышает score «обычной сцены» на порог — это резко снижает ложняки. Уверенность калибруется через сигмоиду от разрыва с baseline.

**NSFW** ([`pz7_nsfw.py`](src/pz7_nsfw.py)). Профильная ViT-модель **Falconsai/nsfw_image_detection**, дообученная именно на порнографии/наготе — точнее zero-shot SigLIP в этой узкой задаче. Возвращает вероятность класса `nsfw` по каждому кадру.

**Действия** ([`pz8_action.py`](src/pz8_action.py)). **X-CLIP** смотрит на **последовательность из 8 кадров**, а не на один — только так можно отличить «драку» от «объятий» или «погром» от «ремонта» по динамике движения. Окна по 8 кадров с 50% перекрытием; softmax по action-промптам против нейтральных. Ловит насилие и вандализм.

**Фьюзия и постобработка** ([`pipeline.py`](src/pipeline.py)). Кросс-модальный boost (если один субкласс независимо нашли и в аудио, и в видео в пересекающихся интервалах — поднимаем уверенность обеим детекциям) → temporal NMS по каждому субклассу (склейка близких событий, дедуп) → отсечение по порогу уверенности.

**LLM-слой (опционально, поверх ядра)** ([`llm.py`](src/llm.py)). Через локальную Ollama:
- контекстная классификация транскрипта (смысл, а не отдельные слова: «поставь всё на красное» → азартные игры);
- vision-проверка пограничных кадров (`use_llm_vision`): подтверждает/отклоняет детекции у порога;
- человекочитаемое резюме отчёта на русском.

Если Ollama не запущена — слой просто пропускается, ядро продолжает работать на алгоритмах (graceful degrade).

## Быстрый старт (GPU)

### 0. Требования

- **Windows** с видеокартой **NVIDIA** (CUDA). Драйвер с поддержкой CUDA 12.8 (Blackwell — RTX 50xx — поддерживается).
- **Python 3.14**.
- Свободное место под окружение с CUDA-сборкой PyTorch — порядка **6 ГБ**. PyTorch с CUDA весит много, поэтому окружение держим на диске с местом (в этой машине — диск `E:`).
- ffmpeg ставить вручную не нужно — `imageio-ffmpeg` приносит бинарник сам.

Окружение вынесено на `E:`, потому что CUDA-сборка PyTorch не помещается на переполненный `C:`. Это обычная изолированная папка venv — на систему никак не влияет, просто запускаем проект её интерпретатором.

```powershell

# CUDA-сборка PyTorch (CUDA 12.8, поддержка RTX 50xx)

    "torch==2.11.0+cu128" "torchvision==0.26.0+cu128" `
```

```bash
curl -X POST http://localhost:8000/analyze/sync \
     -H "Content-Type: application/json" \
     -d '{"url": "https://www.youtube.com/watch?v=XXXX", "preset": "balanced"}'
```

### Загрузка файла (multipart, без интернета)

```bash
curl -X POST http://localhost:8000/analyze/upload \
```

## Легенда: как и почему менялись методы — от практических работ к финалу

> Этот раздел — для защиты курсовой: честно, по-человечески, почему первые версии каналов были одни, а в финале стали другими, и какие метрики я при этом держал в голове.

Здравствуйте! Если коротко — каждый канал в финале решает **ту же задачу**, что и в первых практических работах, но первая версия была учебным «скелетом» (доказать, что подход в принципе работает), а финальная — рабочей реализацией под реальную задачу: меньше ложных срабатываний на настоящих роликах.

Метрику я держал простую и честную для такого формата: на размеченных вручную клипах смотрел **precision** (доля верных срабатываний среди всех — чтобы сервис не «кричал» на пустом месте) и **recall** (какую долю реальных нарушений поймали). Для модерации опаснее ложная тревога на ровном месте, поэтому при выборе порогов я осознанно склонялся в сторону **precision**, стараясь не ронять recall.

**Объекты: с базового YOLO на YOLOv11 + YOLO-World.**
Сначала это был самый лёгкий YOLOv8n на 80 COCO-классах — он отлично показывал саму идею детекции, но в COCO просто нет «сигареты», «шприца», «казино», «свастики». Поэтому в финале добавлен open-vocabulary детектор **YOLO-World**: он ищет объект по текстовому описанию без переобучения. Классический YOLO оставлен для частых объектов (бутылка, нож), где он точнее. Это заметно подняло recall по «редким» категориям, не просев по precision.

**Сцена: с классификатора ImageNet/CLIP на SigLIP 2 с нейтральным baseline.**
В ранней версии сцену описывал обычный классификатор (топ-классы ImageNet) и затем zero-shot CLIP. Проблема: CLIP «срабатывал» почти на всё подряд — абсолютное сходство плавало, и порог приходилось ставить наугад. В финале — **SigLIP 2** плюс ключевая идея: сравниваю кадр не только с промптами категории, но и с набором **нейтральных** промптов («обычная сцена»), и засчитываю нарушение только если перевес над нейтралью больше порога. Это и есть главный рычаг против ложных срабатываний — precision вырос принципиально.

**Речь: с простого поиска слов на морфологию + деобфускацию + контекстный LLM.**
Сначала был наивный поиск подстроки в транскрипте — он ловил «выпил», но спотыкался на падежах и путал «ром» с «романом», а мат, написанный через звёздочки, пропускал. В финале матчер стал морфология-устойчивым (rapidfuzz), добавлена деобфускация мата, а сверху — необязательный LLM-классификатор, который читает **смысл** фразы (контекст экстремизма/азартных игр/угроз). Это подняло и recall (ловим словоформы и обфускацию), и precision (контекст отсекает случайные совпадения).

**Описание кадров: с внешнего облачного API на локальные модели.**
В первых работах описания кадров брались через внешний облачный vision-API (запрос наружу, ключи, лимиты, зависимость от чужого сервиса и региональных блокировок). Для итогового сервиса это неприемлемо: всё перенесено на **локальные** модели (SigLIP, Falconsai NSFW, X-CLIP) и опциональную локальную Ollama. Никаких ключей и внешних запросов — приватность и воспроизводимость результата.

**Новые каналы, которых в начале не было.**
NSFW-детекция отдельной профильной моделью (Falconsai) и распознавание **действий по видео-окну** (X-CLIP) — это уже не «переделка», а ответ на то, что одиночный кадр и словарь физически не различают «драку» и «объятия», а zero-shot плохо чувствует степень обнажённости. Эти каналы закрыли категории, которые иначе ловились ненадёжно.

**Постобработка: с простой склейки соседних кадров на кросс-модальную фьюзию.**
Сначала события собирались простой склейкой соседних кадров одного класса. В финале добавлен **кросс-модальный boost** (согласие аудио и видео — сильный признак, что это не шум) и temporal NMS. Это аккуратнее объединяет события и поднимает уверенность там, где два независимых канала «видят» одно и то же.

Итог: направление каждого канала осталось прежним (объекты, сцена, речь, текст, постобработка), но методы заменены на более устойчивые к реальным роликам, с явным приоритетом на снижение ложных срабатываний при сохранении полноты.

## Метрики на роликах (реальный прогон на GPU)

Замеры сделаны на коротких публичных роликах, инференс на **NVIDIA RTX 5060, 8 ГБ, CUDA**. Время — фактическое время обработки сервисом (холодный старт: включает загрузку моделей в VRAM; на длинных роликах загрузка амортизируется и `efficiency` падает). Все каналы (объекты, сцена, NSFW, действия, OCR, речь) отработали на GPU; в баннере при старте видно выбранное устройство.

<!-- METRICS_TABLE_START -->
| Ролик | Длит. | Пресет | Обработка | Efficiency | Найдено |
|---|---|---|---|---|---|
| анимация без звука (Big Buck Bunny 10s) | 10 с | `fast` | 10.0 с | 1.00 | 2 события (`animal_cruelty`, conf≈0.72) — ложные на мультяшных зверях |
| та же анимация | 10 с | `balanced` | 11.6 с | 1.16 | 2 события (`animal_cruelty` 0.68, `nsfw` 0.46 — пограничное) |
| та же анимация | 10 с | `accurate` | 13.7 с | 1.37 | **1 событие** (`animal_cruelty` 0.55) — крупнее модели → меньше ложных и ниже уверенность |
| природа со звуком (15s, stereo AAC) | 15 с | `balanced` | 16.0 с | 1.03 | **0 событий** — чистый контент, ложных нет; аудио-ветка (Whisper) отработала за 12.5 с |
| та же природа | 15 с | `accurate` | 49.3 с | 3.18 | **0 событий**; so400m + whisper large-v3 + yolo11x — всё уложилось в 8 ГБ VRAM без OOM |

Пер-канальное время (`balanced`, ролик 15 с, холодный старт, из `outputs/logs/service.log`):
keyframes 6.2 с · речь/Whisper 12.5 с · NSFW 5.0 с · сцена/SigLIP 6.3 с · OCR 7.6 с · объекты/YOLO 7.9 с (каналы идут параллельно, поэтому суммарное время ≈ самого долгого).

Что видно по числам:
- **Чистый контент → 0 ложных тревог** (нейтральный 15-секундный ролик на `balanced` и `accurate` — ни одного срабатывания).
- **Крупнее пресет → меньше ложных:** на той же анимации `fast`/`balanced` дали 2 ложных события, а `accurate` — 1, и с меньшей уверенностью. Это та самая ставка на precision из легенды выше.
- **`accurate` помещается в 8 ГБ VRAM** (siglip2-so400m + whisper large-v3 + yolo11x) — за счёт сериализации доступа к GPU (`gpu_guard`), без OOM; платим временем (efficiency 3.18 на холодном старте, на длинных роликах загрузка моделей амортизируется).

> Это **технический** прогон: на нейтральных публичных клипах он показывает скорость, работу всех каналов на GPU и отсутствие ложных тревог на чистом видео. Метрики **качества** (precision/recall) считаются на размеченных вручную клипах с реальными нарушениями — для этого тем же скриптом `benchmark.py` прогоняется свой список ссылок.
<!-- METRICS_TABLE_END -->

Прогнать метрики самому по списку ссылок:

```powershell
E:\cv-venv\Scripts\python.exe scripts\benchmark.py --preset balanced `
    --url "https://www.youtube.com/watch?v=XXXX" `
    --url "https://www.youtube.com/watch?v=YYYY"
```

Скрипт скачает ролики, прогонит пайплайн на GPU и выведет по каждому: число событий по категориям, среднюю уверенность, время обработки и `processing_efficiency` (время обработки / длительность ролика).

**Сохранённые отчёты.** Каждый выходной JSON, который сформировал анализ, автоматически сохраняется в `outputs/reports/` с именем `<дата>_<пресет>_<источник>.json` — независимо от того, пришёл запрос из UI, `/analyze/sync`, `/analyze/upload` или асинхронного режима. Для однозначной идентификации в самом JSON есть поля `source` (ссылка на YouTube либо абсолютный путь к файлу) и `source_dir` (папка, где лежит ролик, для локальных файлов). ## Структура проекта

```
cv-video-analytics/
├── run_ui.py                ← запуск Gradio UI (печатает баннер устройства)
├── run_api.py               ← запуск FastAPI
├── scripts/
│   ├── download_models.py   ← разовая загрузка всех моделей в кэш + offline-маркер
│   └── benchmark.py         ← прогон метрик по списку ссылок (GPU)
├── src/
│   ├── ui.py                ← Gradio-интерфейс с прогресс-деревом
│   ├── pipeline.py          ← VideoAnalyzer: параллельный запуск каналов + фьюзия
│   ├── main.py              ← FastAPI: /analyze, /analyze/sync, /analyze/upload, /status, /result
│   ├── device.py            ← выбор GPU/CPU, сериализация доступа к VRAM, баннер
│   ├── logs.py              ← логи по стадиям (консоль + outputs/logs/service.log)
│   ├── presets.py           ← пресеты fast/balanced/accurate (размеры всех моделей)
│   ├── config.py            ← пути кэша моделей, offline-режим
│   ├── schemas.py           ← Pydantic-схемы (TimeBasedReport, Detection, ...)
│   ├── subclass_info.py     ← справочник 12 категорий (цвета, иконки, severity)
│   ├── llm.py               ← LLM-слой через Ollama (классификация речи, vision, резюме)
│   ├── pz1_keyframes.py     ← ключевые кадры (scene detection + резкость + дедуп)
│   ├── pz3_ocr.py           ← OCR (EasyOCR ru+en)
│   ├── pz4_audio.py         ← Whisper + словарный матчер
│   ├── pz5_yolo.py          ← YOLOv11 (COCO) + YOLO-World (open-vocab)
│   ├── pz6_clip.py          ← сцена (SigLIP 2, нейтральный baseline)
│   ├── pz7_nsfw.py          ← NSFW (Falconsai)
│   └── pz8_action.py        ← действия по видео-окну (X-CLIP)
├── outputs/
│   ├── reports/             ← автосохранённые JSON-отчёты каждого анализа
│   ├── logs/                ← service.log (ход стадий)
│   └── clips/               ← нарезанные клипы событий
├── requirements.txt
└── ПАМЯТКА_ЗАПУСК.md
```

> Имена файлов вида `pzN_*.py` — исторические (модули росли из практических работ). Снаружи это просто каналы детекции; переименование оставлено отдельной задачей, чтобы не ломать импорты на защите.
