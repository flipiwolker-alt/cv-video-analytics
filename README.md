# CV Video Analytics

Учебный проект по компьютерному зрению и анализу видео. Состоит из 8 практических заданий (ноутбуки, Google Colab) и **итогового Gradio-приложения** с полноценным API для детектирования нежелательного контента в YouTube-видео.

---

## Итоговое приложение — Gradio UI + REST API

### Что умеет

- Принимает ссылку на YouTube-видео
- Запускает **параллельный анализ** четырьмя нейросетями:
  - 🎤 **Whisper** — распознавание речи + keyword-классификация
  - 📦 **YOLOv8n** — детекция объектов (бутылки, сигареты и др.)
  - 🧠 **CLIP ViT-B/32** — zero-shot анализ контекста сцены
  - 📝 **EasyOCR** — распознавание текста в кадре (опционально)
- Обнаруживает **12 категорий нарушений**: алкоголь, наркотики, курение, экстремизм, ЛГБТ-пропаганда, насилие, вандализм, азартные игры, нецензурная лексика, **порнография/нагота (NSFW)**, **суицид/селфхарм**, **жестокость к животным**
- Каналы детекции: речь (Whisper + словарь с морфологией и деобфускацией мата), текст в кадре (OCR), объекты (YOLOv11 + YOLO-World open-vocab), сцена (SigLIP 2), NSFW (профильная модель Falconsai), контекст (LLM Qwen2.5 через Ollama)
- Показывает таймлайн событий, карточки с confidence, галерею кадров и вырезки клипов
- Возвращает структурированный **JSON-отчёт**

### Подробно по каждому каналу

#### 📥 Этап 0 — Загрузка видео (`pipeline.py → _download`)
Видео скачивается через **yt-dlp** (YouTube) или принимается как локальный файл (офлайн-демо).
ffmpeg склеивает видео- и аудиодорожки в единый `.mp4`. OpenCV считывает метаданные: FPS, количество кадров, длительность.

---

#### 🎞 Этап 1 — Извлечение ключевых кадров (`pz1_keyframes.py`)
Не анализируем каждый из тысяч кадров — это было бы слишком медленно. Вместо этого:
1. **SceneDetect (ContentDetector)** — находит кадры на границах смены сцены (резкий перепад контента).
2. **Равномерный stride** — дополнительно берём по одному кадру каждые N секунд (зависит от пресета).
3. **Выбор резкого кадра** — из окрестности ±N кадров выбирается самый резкий по дисперсии Лапласиана (отсев смазанных движением кадров).
4. **dHash-дедупликация** — почти-одинаковые соседние кадры (расстояние Хэмминга ≤ 5) отбрасываются.

Итог: набор из 30–150 информативных, разнообразных и резких кадров для передачи в детекторы.

---

#### 🎤 Этап 2 — Аудио-анализ: речь (`pz4_audio.py`)
1. ffmpeg извлекает аудиодорожку → WAV 16 кГц моно.
2. **faster-whisper** (CTranslate2, int8) транскрибирует речь в текст с тайм-кодами по сегментам. Модель выбирается по пресету: `small` / `large-v3-turbo` / `large-v3`.
3. **Словарный матчер** (морфология + rapidfuzz) ищет запрещённые слова по каждой категории. Поддерживает все словоформы («пьёт» / «выпил» / «напился»), не путает похожие слова («ром» ≠ «роман»).
4. **Деобфускация мата** — leet-замены (`б!tch` → `bitch`), символы-маскеры (`з*ебись`), повторы букв (`пьяааный`) нормализуются перед матчингом.
5. Каждый сегмент, в котором найдено нарушение, становится детекцией с тайм-кодом и confidence.

---

#### 🤖 Этап 3 — LLM-классификация речи (`llm.py`)
Параллельно словарному матчеру — и точнее него для контекстных категорий:
- Полный транскрипт делится на окна и отправляется в **Qwen2.5 (Ollama, локально)**.
- LLM читает смысл, а не ищет отдельные слова: «поставь всё на красное в казино» → `ludomania`, «неверные должны быть уничтожены» → `extremism`.
- Возвращает JSON со списком категорий, confidence и цитатой-уликой.
- Если Ollama не запущена — этот шаг пропускается, пайплайн продолжает работать на словаре (graceful degrade).

---

#### 📦 Этап 4 — Детекция объектов (`pz5_yolo.py`)
Два детектора запускаются на тех же ключевых кадрах **параллельно**:

**YOLOv11 (COCO)** — классический детектор, обученный на 80 классах. Уверенно ловит:
- бутылки, банки (→ `alcohol`)
- людей с оружием (→ `violence`)
- сигареты (→ `smoking`)

**YOLO-World (open-vocabulary)** — zero-shot детектор. Принимает текстовые промпты и ищет объекты по описанию, без переобучения. Ловит то, чего нет в COCO:
- «syringe, needle, drugs» (→ `drugs`)
- «spray can, graffiti» (→ `vandalism`)
- «casino chips, playing cards, slot machine» (→ `ludomania`)
- «swastika, extremist symbol» (→ `extremism`)

Детекции обоих детекторов маппятся на 12 субклассов через таблицу соответствия.

---

#### 🧠 Этап 5 — Анализ сцены (`pz6_clip.py`)
**SigLIP 2** (Google, превосходит CLIP по zero-shot точности) кодирует каждый кадр в эмбеддинг и сравнивает с текстовыми промптами по категориям:
- Для каждой категории — ансамбль из 3–5 промптов («a photo of people drinking alcohol», «beer bottles on the table», ...).
- Вводится **нейтральный baseline** — набор промптов нейтральных сцен. Детекция срабатывает только если score категории превышает score нейтрали на заданный порог. Это резко снижает число ложных срабатываний.
- Финальный confidence калибруется по отношению score / threshold.

---

#### 🔞 Этап 6 — NSFW-детектор (`pz7_nsfw.py`)
**Falconsai/nsfw_image_detection** — профильная ViT-модель, дообученная специально на порнографии и наготе. Точнее zero-shot SigLIP для этой задачи (SigLIP обучен на «натуральном» вебе и плохо различает степени обнажённости). Возвращает probability класса `nsfw` для каждого кадра.

---

#### 🎬 Этап 7 — Распознавание действий (`pz8_action.py`)
**X-CLIP** (microsoft/xclip-base-patch32) — видео-модель, которая смотрит на **последовательность из 8 кадров**, а не на один. Только она способна отличить «драку» от «объятий» или «погром» от «ремонта» — по динамике движений.

- Ключевые кадры собираются в окна по 8 (с 50% перекрытием).
- X-CLIP кодирует окно и сравнивает с текстовыми промптами действий.
- Softmax по action-промптам + нейтральным: если нейтраль выигрывает — детекции нет.
- Ловит: `violence` (драки, избиения), `vandalism` (порча имущества, поджог, граффити).

---

#### 📝 Этап 8 — OCR / текст в кадре (`pz3_ocr.py`)
**EasyOCR** (ru+en) читает текст с каждого ключевого кадра.

Предобработка специально для OCR (не применяется к другим каналам, чтобы не портить их распределение):
- Апскейл мелких кадров (до 1280px по длинной стороне).
- CLAHE-контраст по яркостному каналу LAB — делает блёклые надписи читаемыми.
- Тюнинг порогов детектора CRAFT: `text_threshold=0.6`, `low_text=0.3` (ловит мелкий/бледный текст).
- Если текст не найден совсем — пробуются повороты на 90°/180°/270° (для перевёрнутых надписей).

Распознанный текст проверяется тем же словарным матчером, что и речь.

---

#### ⚙️ Этап 9 — Фьюзия и постобработка (`pipeline.py → _postprocess`)
Все детекции из 8 каналов сводятся воедино:

1. **Temporal NMS** (Non-Maximum Suppression по времени) — склеивает близкие детекции одного субкласса в единое событие, убирает дубликаты.
2. **Fusion boost** — если аудио и видео согласно детектировали один субкласс в пересекающихся интервалах, confidence итоговой детекции повышается.
3. **Порог фильтрации** — детекции ниже минимального confidence удаляются.
4. **Temporal NMS финальный** — устраняет остаточные перекрытия между событиями.

---

#### 🔍 Этап 10 — LLM vision-верификация (`llm.py → verify_frame`, опц.)
При включённом `use_llm_vision=true`: пограничные детекции (confidence близко к порогу) отправляются в **Qwen2.5-VL** (мультимодальная LLM). Модель смотрит на кадр и подтверждает или отклоняет детекцию. Срезает ложняки, которые прошли через статистические пороги.

---

#### 📋 Этап 11 — LLM-резюме и отчёт
**Qwen2.5** получает список всех подтверждённых детекций и генерирует краткое человекочитаемое резюме на русском языке. Итоговый `TimeBasedReport` содержит:
- все детекции с тайм-кодами, confidence, типом канала
- `llm_summary` — текстовое резюме
- метаданные (длительность, время обработки, пресет)

Из видео нарезаются клипы ±5 секунд вокруг каждого события и извлекаются кадры-превью для галереи.

#### Загрузка видеофайла (multipart, работает офлайн — без yt-dlp)

Удобно для Postman: метод `POST`, Body → **form-data**, ключ `file` тип **File**,
остальные поля (`preset`, `use_*`) — тип **Text**.

```bash
# Полный анализ загруженного файла
curl -X POST http://localhost:8000/analyze/upload \
     -F "file=@/path/to/video.mp4;type=video/mp4" \
     -F "preset=balanced" \
     -F "use_llm=true"

# Быстрый прогон (без тяжёлых каналов)
curl -X POST http://localhost:8000/analyze/upload \
     -F "file=@/path/to/video.mp4;type=video/mp4" \
     -F "preset=fast" -F "use_ocr=false" -F "use_action=false"
```

Поля form-data: `file` (обязательно), `preset` (`fast`/`balanced`/`accurate`),
`use_clip`, `use_ocr`, `use_nsfw`, `use_action`, `use_llm`, `use_llm_vision`, `whisper_model`.

Параметры запроса:

| Поле | Тип | По умолчанию | Описание |
|------|-----|-------------|----------|
| `url` | string | *обязательно* | Ссылка на YouTube |
| `quality` | string | `720p` | Качество видео: `360p`, `480p`, `720p`, `1080p` |
| `preset` | string | `balanced` | **Ручка точность ⇄ скорость:** `fast`, `balanced`, `accurate`. Раскатывается на все модели сразу (см. ниже) |
| `use_clip` | bool | `true` | Включить CLIP-анализ сцен |
| `use_ocr` | bool | `false` | Включить OCR (медленно) |
| `use_llm` | bool | `true` | LLM-слой (Ollama): контекстная классификация речи + резюме |
| `use_llm_vision` | bool | `false` | LLM vision-проверка пограничных кадров (медленно на CPU) |
| `whisper_model` | string | *из пресета* | Переопределить размер Whisper: `tiny`/`base`/`small`/`medium` |

#### Пресеты точности (`preset`)

Всё считается на CPU, поэтому размер моделей напрямую влияет и на точность, и на время.
Один параметр `preset` выбирает размеры **всех** моделей разом:

| Пресет | Объекты (COCO + open-vocab) | Сцена | Речь (Whisper) | Ориентир (ролик 3 мин) |
|---|---|---|---|---|
| `fast` | YOLOv11s + YOLO-World s | SigLIP2 base/224 | small | ~1–3 мин |
| `balanced` | YOLOv11m + YOLO-World m | SigLIP2 base/384 | large-v3-turbo | ~3–7 мин |
| `accurate` | YOLOv11x + YOLO-World x | SigLIP2 so400m/384 | large-v3 | ~5–15 мин |

**Что нового в точности детекций:**
- **Объекты:** **YOLOv11** (COCO) + **YOLO-World** (open-vocabulary) параллельно. World ловит то, чего нет в COCO: сигареты, оружие, шприцы, граффити, карты/казино, экстремистскую символику.
- **Сцена:** **SigLIP 2** (точнее CLIP по zero-shot, меньше ложняков) + ансамбль промптов + калиброванная уверенность через нейтральный baseline + строгий порог.
- **Речь:** **faster-whisper large-v3 / turbo** (точнее для русского) + морфология-устойчивый матчер (ловит падежи/склонения, не путает «ром» и «роман»).
- **Фьюзия:** при согласии аудио и видео по одному субклассу в пересекающихся интервалах уверенность повышается.

Пример ответа:

```json
{
  "report_type": "TIME_BASED_REPORT",
```

#### LLM-слой (Ollama, бесплатно и локально)

Ядро детекции работает **без LLM** — на алгоритмах. LLM подключается как
необязательный слой поверх (`use_llm`). Если Ollama не запущена, пайплайн
просто продолжает работать на алгоритмах (graceful degrade).

Где применяется:
1. **Контекстная классификация речи** — LLM читает транскрипт и размечает 12 категорий с учётом смысла (точнее keyword-regex для экстремизма/ЛГБТ/угроз).
2. **Резюме отчёта** — краткое человекочитаемое саммари (`llm_summary` в JSON).
3. **Vision-проверка кадров** (`use_llm_vision`) — подтверждает пограничные детекции YOLO/CLIP, срезает ложняки.

Установка (один раз):

```bash
# 1. Скачать Ollama: https://ollama.com/download
# 2. Скачать модели:
ollama pull qwen2.5:7b      # текстовая классификация речи + резюме
ollama pull qwen2.5vl:7b    # vision-проверка (только если use_llm_vision=true)
# Сервис сам поднимается на http://localhost:11434
```

Адрес Ollama можно переопределить переменной окружения `OLLAMA_HOST`.
Модели по пресету: `fast` → `qwen2.5:3b`, `balanced`/`accurate` → `qwen2.5:7b`.

## Подробное описание каждого ПЗ

### ПЗ 1 — Обработка изображений (OpenCV)
**Цель:** освоить базовые операции с изображениями.
**Что происходит:**
- Загрузка одного изображения через OpenCV (`cv2.imread`)
- Применяются преобразования: resize, перевод в grayscale (`cv2.cvtColor`), регулировка яркости/контраста (`cv2.convertScaleAbs`), Гауссово размытие (`cv2.GaussianBlur`), поворот (`cv2.getRotationMatrix2D` + `cv2.warpAffine`)
- Каждое преобразование визуализируется через `matplotlib`

**Вход:** одно изображение
**Выход:** серия преобразованных версий
📓 [PZ_1_OpenCV_Processing.ipynb](notebooks/PZ_1_OpenCV_Processing.ipynb)

---

### ПЗ 2 — Нарезка видео на кадры
**Цель:** подготовить датасет кадров для всех остальных ПЗ.
**Что происходит:**
- Видео загружается на Google Drive, монтируется в Colab (`drive.mount`)
- Через `cv2.VideoCapture` читается покадрово
- Сохраняется каждый N-й кадр (по умолчанию `FRAME_STEP = 30`, т.е. 1 кадр в секунду при 30fps) в формате JPG
- Имена файлов: `frame_000000.jpg`, `frame_000030.jpg` и т.д.

**Вход:** видеофайл на Drive
**Выход:** папка с кадрами `/MyDrive/cv-frames/кадры/`
📓 [PZ_2_Video_Download.ipynb](notebooks/PZ_2_Video_Download.ipynb)

---

### ПЗ 3 — OCR (распознавание текста)
**Цель:** извлечь весь текст с кадров (субтитры, вывески, надписи).
**Что происходит:**
- Используется EasyOCR с поддержкой `['ru', 'en']`
- Каждый кадр прогоняется через `reader.readtext()` — возвращает bounding boxes + распознанный текст + confidence
- Результаты собираются в DataFrame: `frame_num`, `text`, `confidence`, `bbox`
- Сохраняется в CSV

**Вход:** кадры из ПЗ 2
**Выход:** `outputs/ocr_results/ocr.csv`
📓 [PZ_3_OCR_Recognition.ipynb](notebooks/PZ_3_OCR_Recognition.ipynb)

---

### ПЗ 4 — Транскрипция аудио (Whisper)
**Цель:** получить текстовую расшифровку речи из видео.
**Что происходит:**
- Из видео извлекается аудиодорожка через `moviepy` (`VideoFileClip(...).audio.write_audiofile(...)`)
- Загружается модель Whisper `base` (можно заменить на `small`/`medium` для лучшего качества)
- `model.transcribe(audio_path)` возвращает текст + сегменты с тайм-кодами
- Поддерживается мультиязычность (автодетекция языка)

**Вход:** видеофайл
**Выход:** `outputs/transcript.txt` + сегменты с тайм-кодами
📓 [PZ_4_Whisper_Audio.ipynb](notebooks/PZ_4_Whisper_Audio.ipynb)

---

### ПЗ 5 — Детекция объектов (YOLOv8)
**Цель:** найти и классифицировать все объекты на каждом кадре.
**Что происходит:**
- Загружается предобученная YOLOv8n (`yolov8n.pt`) — лёгкая версия для быстрого инференса
- Каждый кадр прогоняется через `model.predict(frame, conf=0.4)`
- Для каждой детекции извлекается: класс (из 80 COCO-классов), confidence, bounding box (x1, y1, x2, y2)
- Опционально рисуются bbox'ы и сохраняется аннотированный кадр
- Все детекции пишутся в CSV: `frame_num`, `class`, `conf`, `x1`, `y1`, `x2`, `y2`

**Вход:** кадры из ПЗ 2
**Выход:** `outputs/detections/detections.csv` + аннотированные кадры
📓 [PZ_5_YOLO_Detection.ipynb](notebooks/PZ_5_YOLO_Detection.ipynb)

---

### ПЗ 6 — Классификация кадров (ResNet50)
**Цель:** для каждого кадра выдать топ-5 классов из ImageNet.
**Что происходит:**
- Загружается ResNet50 с весами ImageNet (`torchvision.models.resnet50(weights=ResNet50_Weights.DEFAULT)`)
- Кадры предобрабатываются: resize 224x224, нормализация по ImageNet mean/std
- `softmax(model(x))` → топ-5 индексов → имена классов
- Визуализация: кадр + подпись с топ-5 классами и вероятностями

**Вход:** кадры из ПЗ 2
**Выход:** `outputs/classifications/classifications.csv` (frame, top5_classes, top5_probs)
📓 [PZ_6_ResNet_Classification.ipynb](notebooks/PZ_6_ResNet_Classification.ipynb)

---

### ПЗ 7 — Описание кадров через LLM (OpenRouter)
**Цель:** получить семантическое описание сцены на каждом кадре через мультимодальную LLM.
**Что происходит:**
- Кадры из Drive отправляются POST-запросом на собственный FastAPI-сервер (`http://92.51.37.40:8000/describe`)
- Сервер кодирует изображение в base64 и шлёт в OpenRouter API
- Используется бесплатная модель `nvidia/nemotron-nano-12b-v2-vl:free` (vision-language)
- Промпт: `"List all objects visible in this image, one line, comma separated"`
- Ответ — список объектов на английском
- Реализован retry-механизм (3 попытки с задержкой 10с) на случай rate-limit
- Результаты собираются в JSON

**Зачем свой сервер:** OpenRouter блокирует запросы из РФ. Сервер с европейским IP служит прокси.

**Вход:** кадры из ПЗ 2
**Выход:** `outputs/llm_descriptions.json` + визуализация кадров с подписями
📓 [PZ_7_LLM__API.ipynb](notebooks/PZ_7_LLM__API.ipynb)

---

### ПЗ 8 — Постобработка результатов
**Цель:** превратить сырые данные из ПЗ 3, 5, 7 в осмысленный отчёт.
**Что происходит:**

**OCR (из ПЗ 3):**
- Дедупликация почти-одинаковых строк через `rapidfuzz.fuzz.ratio` (порог 85%)
- Удаляет повторы вроде "Hello world" и "Hello wrld" — оставляет одну версию

**YOLO (из ПЗ 5):**
- Группировка детекций по классу
- Склейка соседних кадров одного класса в "событие" (если разрыв ≤ 5 кадров)
- Получаем: `class`, `start_frame`, `end_frame`, `avg_conf` — вместо тысяч точечных детекций ~десяток событий

**LLM (из ПЗ 7):**
- Парсинг описаний, подсчёт частоты упоминаний объектов
- Топ-10 самых частых объектов в видео

**Итог:** сводный JSON-отчёт + графики (распределения, временные шкалы)
📓 [PZ_8_PostProcessing.ipynb](notebooks/PZ_8_PostProcessing.ipynb)

## API endpoints

### `GET /`
Health-check. Проверяет, что сервер жив и API-ключ загружен.

# Здесь мы выполняем простой GET-запрос на корневой адрес и получаем подтверждение работоспособности сервиса

**Ответ:**
```json
{ "status": "ok", "api_key_loaded": true }
```

---

### `POST /describe`
Описание одного изображения. Принимает файл, возвращает список объектов.

# Здесь мы отправляем на сервер изображение в виде multipart-формы и получаем перечень объектов, найденных на нём

**Запрос:**
```bash
curl -X POST http://92.51.37.40:8000/describe \
  -F "file=@frame.jpg"
```

**Ответ:**
```json
{
  "objects": "person, car, building, traffic light, road",
  "filename": "frame.jpg"
}
```

**Что делает:**
1. Принимает multipart-файл
2. Открывает через PIL, конвертирует в RGB, кодирует в base64
3. Шлёт в OpenRouter с промптом "list objects"
4. Retry × 3 с задержкой 10с при ошибках
5. Возвращает текст объектов

---

### `POST /describe-video`
Описание видео по ссылке. Скачивает видео, нарезает на кадры, описывает каждый.

# Здесь мы передаём серверу ссылку на видео и интервал между кадрами, а в ответ получаем описание содержимого видео с разбивкой по тайм-кодам

**Запрос:**
```bash
curl -X POST http://92.51.37.40:8000/describe-video \
  -H "Content-Type: application/json" \
  -d '{"url": "https://www.youtube.com/watch?v=...", "interval_sec": 5}'
```

**Параметры:**
- `url` (обяз.) — ссылка на видео (YouTube, прямая ссылка на mp4 и др. поддерживается через `yt-dlp`)
- `interval_sec` (опц., по умолчанию 5) — интервал между анализируемыми кадрами в секундах

**Ответ:**
```json
{
  "url": "...",
  "frames_analyzed": 12,
  "results": [
    {"time_sec": 0,  "objects": "person, microphone, stage"},
    {"time_sec": 5,  "objects": "car, road, sky"},
    {"time_sec": 10, "objects": "..."}
  ]
}
```

**Что делает:**
1. `yt-dlp` скачивает видео во временную папку
2. `cv2.VideoCapture` определяет FPS, читает покадрово
3. Каждый `interval_sec * fps`-й кадр кодируется и шлётся в OpenRouter
4. Результаты с тайм-кодами агрегируются в JSON
5. Временные файлы удаляются после обработки

**Время ответа:** зависит от длины видео и `interval_sec`. Для 1-минутного видео с шагом 5с ≈ 12 кадров × 5-10с = 1-2 минуты.
